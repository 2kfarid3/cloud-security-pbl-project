# Baseline Run Summary (Phase 2)

3 repetitions × 4 scenarios = 12 case executions, all `exit_code=0` / `validity=valid`. Raw data: `results/baseline_run_manifest.csv` (run metadata) + `results/baseline_run_results.csv` (per-run alert counts, generated by `scripts/parse_falco_events.py` from the raw Falco JSONL in `evidence/raw/phase2_baseline/`, which is kept locally only — see `.gitignore`).

| Case | Repetitions valid | Raw alert count (per run) | Deduplicated alert count (per run) | Rules fired |
|---|---|---|---|---|
| `normal` | 3/3 | 8, 8, 8 | 6, 6, 6 | `PBL Normal Configuration Read`×2, `PBL Normal Curl Health Check`×1, `PBL Normal Temporary File Activity`×3 |
| `abnormal_1` | 3/3 | 2, 2, 2 | 2, 2, 2 | `PBL OpenMetadata Environment Discovery`×2 |
| `abnormal_2` | 3/3 | 1, 1, 1 | 1, 1, 1 | `PBL OpenMetadata ServiceAccount Token Access`×1 |
| `abnormal_3` | 3/3 | 2, 2, 2 | 2, 2, 2 | `PBL OpenMetadata Payload Execution`×2 |

Every repetition of every case produced an identical, deterministic result — no flaky runs in this sample. "Deduplicated" collapses the cross-node echoes of the same real syscall (see `docs/baseline_analysis.md`, "Cross-node event visibility"); the raw/deduped gap for `normal` (8 → 6) is entirely explained by the `PBL Normal Curl Health Check` rule's lack of a `container.name` scope, which lets its single real event be independently observed and logged by all 3 Falco pods.

**What this is not yet:** this is baseline-rule behavior only (Phase 2), confirming Phase 1's predictions. It is not yet a TP/FP/FN/TN scored evaluation — that requires the expanded test matrix (Phase 3) and the baseline-vs-improved comparison (Phase 5). In particular, every `abnormal_*` run here fired its intended rule with no missed detections (0/3 FN across all three malicious scenarios) and every `normal` run fired only the three expected benign rules with no stray `abnormal_*` rule ever matching (0/3 FP so far) — but this is 3 samples of 4 specific, narrow, already-known-to-match cases, not a measurement of the rules' false-positive rate against new/harder normal variants. That measurement is exactly what Phase 3's additional test cases exist to produce.

## Known collection-process bug found and fixed during this phase

An earlier draft of this dataset (discarded, not committed) double- and quadruple-counted several runs because the log collector (`kubectl logs -f`, no `--since-time`) replays a pod's entire buffered history every time it is (re)started — so restarting the collector mid-session caused the same historical events to appear twice across old and new output files. Fixed by adding `--since-time=<now>` to `scripts/collect_falco_logs.sh`. A second, smaller bug (the per-run analysis window's "catch delayed alerts" trailing buffer being longer than the ~10s gap between consecutive case executions) caused a run's window to swallow the *next* run's alerts too; fixed in `scripts/parse_falco_events.py` by capping each run's window at the next run's start time. Both fixes are in the committed scripts; the numbers in this file are from the corrected pipeline, re-run end to end.
